# Bilibili study notes

If `references/local-runtime.md` exists, read it first and use its installed launcher/environment rather than the system Python. This file is a private machine-specific overlay.

Process one user-provided video or `?p=N` part per invocation. Set `BILIBILI_NOTES_VAULT` to the root of your Obsidian vault before publishing or cleaning staging files; publish notes to `Video Notes/History/` or `Video Notes/Literature/` and all selected frames to the single `Video Notes/assets/` folder. Record the uploader as `creator`. When a title or source metadata clearly identifies a series, record its name in `series`; when a title ends in a series marker such as `P2`, use it as `series_part` and the filename suffix; keep `part` for the Bilibili page index (`?p=N`). Frame filenames include the BV ID, series/page part and timestamp to prevent collisions. Use English file and folder names or BV IDs. Do not write in fiction canon folders.

Read `references/quality-and-progress.md` when writing/reviewing full prose, handling cut boundaries, or reporting progress. Use the launcher `doctor` command before media processing.

## Workflow

1. From this skill folder, run `python scripts/video_pipeline.py prepare URL --workdir WORKDIR` with a unique workdir. The script checks for subtitles, then uses local Qwen3-ASR 0.6B via Apple MLX if needed. It processes one audio chunk per child process to release model memory, but may still make a 16 GB Mac sluggish; do not run several ASR jobs together. Add `--hotwords '...'` only for terms supported by source metadata or inspected frames. If login is needed, retry with `--browser chrome` after checking the browser; never expose cookies. Whisper is not used in this deployment. Qwen defaults to 60-second chunks; use `--chunk-seconds 30` for a shorter bounded run. Read `references/asr-options.md` only when comparing recognizers.
2. Read the manifest, raw transcript and contact sheet. Inspect candidates and use `python3 scripts/video_pipeline.py select WORKDIR --indices 1,4,...` to keep a few informative full-resolution PNGs. Re-run with the complete desired list to revise. Maps, dates, source text and diagrams are useful. A film scene is illustration, not evidence.
3. Run `python scripts/video_pipeline.py draft WORKDIR` to build a simplified-Chinese, time-aligned editing scaffold at `transcript_draft.md`. This only converts script, joins segments and inserts image placeholders; it does not repair recognition errors. For the subsequent text editing/generation stage, select **GPT-6 Luna** in Codex when the app allows model selection. A skill cannot switch the running chat's model by itself. If this chat is not Luna, use the user's model switch or, when the user has explicitly authorized delegation, a GPT-6 Luna subagent for `note.md` drafting. Before delegating, read the Luna handoff instructions in `references/note-format.md` and give the writer direct access to `transcript.md`, `transcript_draft.md`, `manifest.json`, the selected-frame list, and any existing `note.md`; do not rely on only the video title, summary, or scaffold. Require a complete-source coverage check before accepting the draft. The parent validates and publishes. Report which model actually edited the text. Local media and ASR commands do not require a Codex language model. Do not call a paid external API to simulate Luna.
4. Write `note.md` in simplified Chinese following `references/note-format.md`. Keep original `title` and `creator`; record a clearly identified series in `series`; distinguish Bilibili `part` from an optional title-derived `series_part`. For History notes, add a `dynasties` list of the main dynasties materially covered and Obsidian nested tags for `UP主/<creator>`, `系列/<series>` when known, and `朝代/<dynasty>` for each listed dynasty. Keep these stable classification tags separate from original Bilibili `video_keywords` and transcript-derived `content_keywords`; do not tag every passing mention. Literature notes use the same creator/series convention but do not get dynasty tags. Derive `video_keywords` only from useful original tags in `manifest.source_tags`; derive `content_keywords` from the entire transcript, not just the title. History: events, dates, people, institutions. Literature: works, concepts, devices and subtopics. Ground claims in audio or inspected frames; mark uncertain names, quotes and factual claims. Rewrite the **entire** relevant spoken content into paragraphed prose without segment timestamps. Keep meaningful detail and sequence, remove ads, ASR debris and filler, and place each selected picture near its relevant passage with a short accurate caption. Never call unverified ASR a verbatim transcript.
5. Run `python scripts/video_pipeline.py coverage WORKDIR` once to create `coverage.json`. Create an item inventory from the full source, not from the draft. Review every event, person, argument, example, qualification and transition against the final full prose using `quality.json`; uncertain names/years/quotes require inspected evidence or a visible uncertainty marker. Review every timestamped source segment against the final full prose. Set each decision to `included`, `omitted`, or `mixed`, and record the matching prose and any omission reason in `evidence`. Set `reviewer` and the SHA-256 of final `note.md` in `note_sha256`. Do not populate this review mechanically or treat hashes as proof of semantic coverage. Changes to the source or note require renewed review. Run `quality WORKDIR` and complete its source/note anchors and doubt review. Then run `python3 scripts/video_pipeline.py publish WORKDIR --category History` (or `Literature`). It validates and publishes the note plus named frames in the shared assets folder without overwriting existing output. After confirming the published files match the staged files, it deletes downloaded media, WAVs, and candidate previews. Use `--keep-media` when follow-up tests require the source; this still performs publication readback. Check `removed_staging_files` or `cleanup_error` in its output; report any cleanup failure. For an already published note, run `python3 scripts/video_pipeline.py cleanup WORKDIR --category History` after making sure the staged note matches the published one. Report path, source, image count, ASR uncertainties and actual text model used.

## Boundaries

- Keep `manifest.json`, raw `transcript.md`, Qwen checkpoints, the staged note, and selected frames for audit. Delete bulky media only after the final note and images have been verified in Obsidian; retain everything on failure. Model weights stay cached for future local runs.
- If subtitle extraction or ASR fails, report the failure instead of generating a complete-looking note from the title or description.
- For an existing note revision, preserve a backup before replacing it; avoid rewriting images unless selection changes.

## Runtime and recovery

Use the installed launcher/environment for pinned dependencies. Qwen reads only the requested audio windows; one fresh model process handles each chunk. `qwen_checkpoint.json` binds checkpoints to source/WAV SHA-256, model, hotwords, cut plan and chunk size. Restart the same command to resume after interruption; use a new workdir if any input or configuration changes. Legacy JSONL checkpoints remain untouched and require a new workdir. Corrupt checkpoints fail closed; preserve them for investigation. A host-wide advisory lock prevents overlapping local ASR jobs. `resources` records each worker’s wall time, maximum RSS (macOS bytes), and MLX allocator peak, which are distinct measurements. Existing prepared manifests still refuse a repeated prepare: continue with select/draft/coverage/publish. Publication refuses existing targets. Never migrate historical checkpoint or note files without a separate user request.

Local installation updates: `scripts/manage_install.py install SOURCE TARGET --backups BACKUP_DIR` creates a rollback archive and preserves the installed private runtime overlay. `rollback ARCHIVE TARGET` restores code while retaining current private settings. Independent JSON machine configuration stays outside TARGET and is never overwritten. See the private runtime overlay for the exact launcher/config paths.
